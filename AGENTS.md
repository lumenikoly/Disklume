# ClearMap: правила изменения проекта

Перед изменениями прочитать README.md, docs/ARCHITECTURE.md и docs/SAFETY.md.

- Действия над реальными файлами находятся только в Rust. Интерфейс передаёт scanId и fileId, не произвольный путь.
- Любое удаление проходит через план и подтверждённую ревизию плана. Никогда не добавлять автоматический переход к безвозвратному удалению.
- Не расширять права Tauri до произвольных файловых или командных операций.
- Не обходить символические ссылки, точки перенаправления и недоступные файлы. Проверять идентичность перед действиями.
- Смена сессии и изменения плана сериализованы общим mutation-замком. Тяжёлая работа выполняется вне потока интерфейса.
- Полный индекс остаётся в ядре. В интерфейсе ограничены число объектов карты и размер страницы.
- Не обещать освобождение места при перемещении в Корзину. Размер выделенных блоков — оценка, не гарантированно освобождаемый объём.
- DemoBackend работает только с искусственными данными. Не подключать к нему нативные операции.
- Не добавлять библиотеку состояния, физический движок или сервер без конкретной измеренной необходимости.
- Файловые тесты используют временные каталоги и TestTrash, никогда настоящую Корзину.

Проверки: npm run typecheck; npm test; npm run test:e2e; cargo fmt --all;
cargo clippy -p clearmap-core --all-targets; cargo test -p clearmap-core;
npm run tauri -- build --no-bundle.

Не заявлять прохождение проверки, которая не запускалась. Актуальные результаты
и ограничения по платформам записаны в docs/VERIFICATION.md.
